# Layout tipográfico medido — compatibilidade antes da implementação

Arquivos previstos: `domain/studios/typography.py`, compilador de receitas/projeção existentes, novo helper DOM original do worker e `hybrid.tsx`. `CreativeDocumentV1`/`MotionRecipeV1` conservam campos e versões. Operação compilada passa a `res.native-recipes.v3`, component library 5 e provider native.7; v1/v2 continuam legíveis com o comportamento anterior. Unidades de texto conservam `studio.typography-units.v1` e recipeTypography version 2. Uma política tipada `studio.typography-layout-policy.v1` em propriedades/operação define o novo layout e entra nos digests.

Novas compilações de `integrated_type` medem a lista de unidades realmente montada, após carregar a fonte: wraps, linhas, altura, caixas e métricas de ink do font engine. O ajuste respeita o tamanho solicitado ou reduz até o piso existente de legibilidade (canvas width × 16/300, mínimo 8 px), sem reescrever texto, trocar fonte ou alterar coordenadas authored. Quando não cabe nesse piso, o render para com target/frame/correção. Pedido de fontSize e tamanho efetivamente aplicado permanecem distintos no diagnóstico.

Medição local usa espelho DOM sem as transformações de entrada/pais; conserva spans, whitespace, fonte, peso, spacing, line-height e largura. Range/linhas são layout; ink por Canvas TextMetrics com a mesma fonte é evidência de métricas do font engine, não coverage de pixels. Geometria mundial continua vindo do DOM real. O hold/timing não é recalculado por uma segunda segmentação. Caso sem font asset declarado registra origem de plataforma não fixada; fonte declarada mantém checksum/glyph checks existentes.

Leitores: lowering/manifesto, capabilities/preflight V2, worker e recibos de geometria. Planos anteriores que precisem da nova semântica são recompilados explicitamente; nenhum snapshot antigo é modificado na leitura. Limites: até 2.000 unidades de layout, 18 iterações de busca e cache de 128 entradas por contexto/browser com digest da composição, fonte/estilo/política na chave. Não há cache persistido ou segundo modelo de projeto.

Aceites previstos: fonte final/checksum, palavras inteiras, acentos, múltiplas linhas/whitespace, palavra muito longa e caixa pequena, piso de tamanho, spacing/peso em frames distintos, grupo com scale/rotation, repouso/hold estáveis e negativos sem MP4 publicado. Prova principal por API → job → MP4/QC; provas DOM/font/pixels são nomeadas separadamente. Revisão humana, celular e adequação editorial permanecem pendentes.

Referências primárias: [CSSOM View: Range rectangles](https://drafts.csswg.org/cssom-view/#dom-range-getclientrects), [CSS Font Loading](https://www.w3.org/TR/css-font-loading-3/), [HTML Canvas text metrics](https://html.spec.whatwg.org/multipage/canvas.html#textmetrics). Motion Canvas `TxtLeaf.ts` no commit fixado foi relido como referência de uso de Range; helper será implementação original, sem copiar esse código.
