# Tipografia canônica — compatibilidade registrada antes da alteração

Arquivos: `domain/studios/typography.py`, `services/studios/native_motion_recipes.py`, `providers/studios/remotion_projection.py`, leitores de capabilities em `contextual_editing_v2.py`, runtime `hybrid.tsx` e runner. `CreativeDocumentV1` e `MotionRecipeV1` mantêm schema/campos; a operação compilada passa de `res.native-recipes.v1` para `res.native-recipes.v2`, com component library 4 e provider native.6. Documentos recompilados ganham novo digest. Leitura não recompila snapshots históricos; planos com versão de execução antiga seguem o diagnóstico existente para recompilação.

Em compilação v2, `character` significa extended grapheme cluster Unicode 17, sem normalizar conteúdo. O segmentador é `regex==2026.1.15` (já instalado localmente; passa a dependência explícita). A palavra permanece bloco não-whitespace; não alegamos segmentação linguística de palavras. Whitespace usa a propriedade Unicode White_Space, é preservado integralmente e não recebe índice animado. Backend determina as unidades e seus índices; manifesto e renderer usam esses dados. A política registra pacote/Unicode e digest do texto UTF-8. A lista materializada e sua validação entram no digest canônico; texto diferente sob o mesmo ID, índices incoerentes ou lista divergente bloqueiam execução. Holds usam a mesma contagem dos spans.

Leitores aceitam operações v1 anteriores com a semântica legada (codepoints e contagem antiga), e v2 com unidades tipadas. Renderer não resegmenta v2 via ICU/Intl; dependência de versões distintas do browser não decide o timing. Componente nativo `integrated_typography` V1 mantém seu comportamento existente neste incremento; a correção aplica-se à receita `integrated_type`. Não declarar toda tipografia corrigida a partir dessa mudança.

Testes de compatibilidade: snapshots v1 sem lista continuam compiláveis; v2 valida roundtrip do texto, Unicode composto/decomposto, ZWJ/flags/tons de pele/Hangul/Indic, whitespace e hold exato. Vetores oficiais `GraphemeBreakTest` Unicode 17 serão confrontados com o segmentador fixado. Prova real: API → plano/documento → job → MP4/checksum/QC, geometria dos spans e frames decodificados. Fontes e métricas finais, fallback de glyph, wraps e leitura humana continuam exigindo evidência própria; segmentação íntegra não demonstra legibilidade.

Fontes primárias: [UAX #29 Unicode 17](https://www.unicode.org/reports/tr29/tr29-47.html), [documentação do pacote fixado](https://pypi.org/project/regex/2026.1.15/), [vetores oficiais](https://www.unicode.org/Public/17.0.0/ucd/auxiliary/GraphemeBreakTest.txt).
